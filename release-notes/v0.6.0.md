# v0.6.0 — Interface multilingue

L'intégration s'affiche désormais dans la langue de Home Assistant.
Espèces, stades phénologiques, niveaux de risque, noms de capteurs :
tout est traduit en français et en anglais, et bascule automatiquement
selon la langue de l'utilisateur.

## ⚠️ Changement de comportement à connaître

**Les entités changent de valeur d'état.** Elles exposent maintenant une
clé technique là où elles affichaient du texte français :

| Entité | Avant | Après |
|---|---|---|
| `select` stade | `Pommier — Pleine floraison` | `full_bloom` |
| `sensor` stade | `Pleine floraison` | `full_bloom` |

L'interface affiche toujours « Pleine floraison » (ou « Full bloom » en
anglais) : c'est Home Assistant qui traduit la clé à l'affichage. Mais
**une automatisation qui compare le texte français cesse de
fonctionner** :

```yaml
# Ne fonctionne plus
condition:
  - condition: state
    entity_id: sensor.pommier_stade_phenologique
    state: "Pleine floraison"

# À la place
condition:
  - condition: state
    entity_id: sensor.pommier_stade_phenologique
    state: "full_bloom"
```

L'historique antérieur conserve les anciennes valeurs : un graphique à
cheval sur la mise à jour montrera les deux formes.

Aucune action n'est requise sur la configuration elle-même : les espèces
et stades étaient déjà stockés sous forme de clés. **Il n'y a donc pas de
migration d'entrée**, et vos arbres, réglages et traitements sont
conservés tels quels.

## Le préfixe d'espèce disparaît des options

Le stade s'affichait « Pommier — Pleine floraison » pour distinguer les
arbres entre eux. L'option est maintenant « Pleine floraison » seule :
un état traduit ne peut pas être composé dynamiquement.

La distinction n'est pas perdue pour autant — elle vient du nom de
l'appareil, chaque arbre étant déjà un appareil distinct. L'entité
s'affiche « Pommier Golden du fond — Stade phénologique », ce qui est la
convention Home Assistant.

## Détail des surfaces traduites

- listes du config flow : espèces, stades, modèles de risque à activer ;
- options de l'entité `select` du stade phénologique ;
- états des capteurs de risque (aucun / à surveiller / alerte / danger) ;
- états du capteur de source de données ;
- noms de toutes les entités (capteurs, `select`, `switch`).

Les notifications restent en français : Home Assistant n'offre pas de
mécanisme déclaratif pour le texte libre. Les événements
`meteo_sentinelle_risk_changed` et `meteo_sentinelle_stage_advanced`
restent disponibles pour composer vos propres messages, via le blueprint
fourni.

## Sous le capot

- les libellés sortent du code Python et vivent dans `strings.json` et
  `translations/` ;
- `strings.json` devient anglais, conformément à la convention Home
  Assistant (la source des traductions) ;
- 35 nouvelles vérifications garantissent qu'aucune clé exposée à
  l'interface ne peut se retrouver sans traduction — le cas silencieux
  où Home Assistant afficherait `full_bloom` à l'utilisateur.
