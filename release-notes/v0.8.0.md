# v0.8.0 — English first

Most users run Home Assistant in English. The integration now follows the
standard approach: **English by default, French as a translation.**

## Documentation

`README.md` is now in English — it is the file HACS displays on the
integration page. `README.fr.md` holds the French version, and a language
switcher sits at the top of both.

## Notifications are translated

Built-in notifications used to be French-only, hardcoded in Python. They
are now composed at runtime from the translation files, in the user's
language, falling back to English.

The wording lives under the `common` key of `strings.json`. That is the
only top-level category that is simultaneously accepted by hassfest,
flat, and allowed to carry `{...}` placeholders — a custom category
would have failed CI.

## Bilingual blueprints

Home Assistant offers no translation mechanism for blueprints, so each
language ships as its own file:

| English | French |
|---|---|
| `frost_protection.yaml` | `protection_gel.yaml` |
| `risk_alerts.yaml` | `alerte_meteo_sentinelle.yaml` |

A test checks that each pair stays structurally identical — same inputs,
same defaults, same triggers — so only the wording can diverge.

## What was already in place

Since v0.6.0 the interface itself was already following this strategy:
English keys in the code, `en.json` as the mandatory fallback, `fr.json`
for French. This release completes it on the surfaces that were left out.

## Also in this release

- the French README no longer claims that stage options are prefixed with
  the species: that stopped being true in v0.6.0;
- the roadmap was several versions behind and has been brought up to
  date in both languages.
