# v0.7.0 — Blueprints prêts à l'emploi

Deux automatisations toutes faites, installables en un clic depuis le
README. Plus besoin d'écrire du YAML pour être prévenu d'un gel.

## Protection contre le gel

Le blueprint prévient au franchissement du seuil choisi et peut, en
option, **allumer un dispositif de protection** — câble chauffant,
aspersion, bâche motorisée, prise connectée — puis le couper quand le
risque retombe.

Le message compare la minimale attendue au seuil de dégâts du stade en
cours : c'est cette comparaison qui rend l'alerte exploitable, −2 °C
n'ayant pas le même sens en dormance qu'en pleine floraison.

Sans dispositif renseigné, le blueprint se comporte comme une simple
alerte gel. Il peut aussi être limité à certains arbres.

## Alertes tous risques

Le blueprint existant est désormais correctement référencé et
installable en un clic (le README pointait vers un nom de fichier qui
n'existait pas).

## Déclenchement au franchissement, pas à chaque variation

Les deux blueprints ne réagissent qu'au **passage** du seuil. Rester en
alerte ne renotifie pas ; repasser en dessous déclenche la remise à
l'état normal. Sans cela, une nuit de gel produirait une notification
tous les quarts d'heure.

## Pourquoi une installation manuelle

HACS n'installe que `custom_components/` : un blueprint placé dans le
dépôt n'arrive jamais chez l'utilisateur. Les boutons « Ouvrir dans Home
Assistant » du README passent par le mécanisme officiel d'import de
blueprint, à faire une seule fois.

## Sous le capot

- 17 nouvelles vérifications sur les blueprints : entrées déclarées et
  utilisées, valeurs par défaut obligatoires dans les sections repliées,
  `min_version` présent, et surtout **événements écoutés cohérents avec
  ceux réellement émis** par l'intégration ;
- PyYAML est installé en CI : sans lui ces contrôles s'ignoraient en
  silence ;
- `scripts/check_integration.py` tourne maintenant aussi en CI.
