# v1.0.1 — hassfest fix

`manifest.json` had its keys in the wrong order. hassfest requires
`domain`, `name`, then strict alphabetical order, and fails the whole
validation otherwise:

```
[MANIFEST] Manifest keys are not sorted correctly: domain, name, then alphabetical order
```

The mistake was introduced in v0.8.0, when `after_dependencies` was added
to declare the `recorder` dependency: the key was placed where it read
best rather than where the tool demands it. Nothing about the
integration's behaviour was affected — only the validation.

`scripts/check_integration.py` now reproduces this rule, so the error is
caught before pushing rather than in CI.
